# 26E_vision 拼图块识别方案十轮选型

## 1. 当前任务边界

目标是识别上半区 1--4 个不重叠的拼图块，输出每块在 A4 平面内的多边形、中心、朝向和候选拾取点，并依据边界互补关系求解为完整位于下半区、约 90--120 mm × 50--90 mm 的目标矩形。基础题、发挥题一和发挥题二动作后均重新扫描复核；发挥题二先复用发挥题一闭环，再用花纹评分在非唯一或近似等价的几何解中择优。最终只输出 `PASS`、`RETRY` 或 `FAIL`。

当前项目已经具备 `puzzle_perception_node -> puzzle_solver_node -> puzzle_coordinator_node` 主链路；Jetson 无有效图像时能够输出 `A4_NOT_FOUND` 并拒绝向控制侧发送猜测坐标。真实拼图图像、A4 映射精度、轮廓精度和唯一解仍未完成实测，因此本文的“最佳”是经过约束分析收敛出的首选工程方案，不代表尚未取得的现场指标已经达标。

## 2. 十轮迭代记录

| 轮次 | 主要候选/问题 | 结论 | 保留理由或淘汰理由 |
|---|---|---|---|
| 1 | YOLO 检测框 vs OpenCV 几何分割 | 保留 OpenCV 为主 | 题目目标是轮廓、顶点和接缝，不是类别框；检测框不能替代精确边界。 |
| 2 | 固定 A4 四角 vs 每帧寻找 A4 | 固定相机映射 + A4 四角运行校验 | 相机固定时固定外参最稳定；每帧仍需检查 A4，检测不到就拒绝。运行时不重估固定相机到工作区映射。 |
| 3 | 直接像素坐标 vs 平面单应性 | A4 矩形化后统一到 mm | 先 `getPerspectiveTransform/warpPerspective`，再做轮廓和求解；任何尺寸、距离和角度都不直接由原图像素解释。 |
| 4 | 独立对象 HSV、Otsu、自适应阈值、Lab 背景距离 | 绿纸背景优先，HSV 只作回退 | 基础题和发挥题一在 A4 内动态采样绿色纸面 Lab 背景并反选纯色/纯白碎片；发挥题二同样采样浅绿色纸面以保留扑克牌完整轮廓。阈值全部保留在 YAML。 |
| 5 | 连通域 vs `findContours` | `findContours(RETR_EXTERNAL)` + 形态学 | 拼图块数量少且要求外轮廓；面积、区域、顶点数和边长约束便于拒绝噪声。连通域仅作统计/诊断，不作为最终顶点来源。 |
| 6 | `approxPolyDP` 单次近似 vs 直线拟合/亚像素细化 | 多边形初值 + 边直线拟合 + 交点细化 | 单次近似对阈值和像素锯齿敏感；最终顶点应由边段拟合和交点给出，必要时用 `cornerSubPix`，并以重投影/轮廓残差做质量门控。 |
| 7 | 全排列刚体搜索 vs 小规模子集动态规划 | 子集 DP + 二叉合并 | 碎片最多 4 块，子集 DP 可穷举且易检查无重叠、矩形闭合、尺寸和唯一性；端到端网络布局不可解释且难加硬约束。 |
| 8 | 仅边长/端点 vs 加入纹理连续性 | 几何硬约束优先，ZNCC/SSIM 接缝纹理为软评分 | 白色区域纹理弱时不能依赖 ORB；有图案时沿接缝法向采样归一化相关性，边界内侧紧挨花纹的边优先比较，只用于几何可行候选排序，ORB+RANSAC 仅作辅助证据。 |
| 9 | 单帧识别 vs 多帧选清晰帧 | 稳定帧采集 + 清晰度最高帧 | 当前实现已按 Laplacian 清晰度选择帧；还需加入计数/轮廓签名一致性，避免单帧误分割直接进入求解。是否动作后复扫按题目流程执行。 |
| 10 | 永远输出最佳解 vs 置信度门控 | `PASS/RETRY/FAIL` 三态门控 | 重叠、孔洞、尺寸越界、映射未验证或 A4 缺失时拒绝输出；分差门槛只在显式配置时启用，牌面题默认用花纹软评分择优。 |

## 3. 最终推荐处理顺序

1. **固定相机采集与质量筛选**：采集有限连续帧，使用清晰度和轮廓稳定性选择代表帧；相机打开、取帧失败记录 `BUG_POINT` 并停止本次扫描。
2. **A4 四角检测与排序**：优先使用实测固定四角；运行时检查四边形、面积比例、长宽比和凸性。失败输出 `A4_NOT_FOUND`。
3. **平面校正**：使用 `getPerspectiveTransform` 将 A4 映射到 210 × 297 mm 的矩形图；只有经实测验证的工作区单应性才允许输出绝对工作区坐标。
4. **前景分割**：先用 `green_a4_*` HSV 获取绿纸/绿框；基础题和发挥题一在 A4 内动态采样绿色纸面 Lab 背景并提取非纸面前景，`white_piece_*` HSV 只作为显式关闭该入口后的回退；发挥题二同样在 A4 内动态采样浅绿色纸面 Lab 背景以保留扑克牌完整外轮廓。三者均排除页面边缘、上下分界线和已知电磁铁颜色。
5. **拼图块轮廓提取**：`findContours` 获取外轮廓，按面积、区域、最大 5 边、最小边长和面积一致性过滤；对保留轮廓进行直线拟合、交点细化和残差评估。
6. **几何特征输出**：生成按顺序排列的 A4-mm 顶点、中心、方向、面积、最大内接圆拾取候选点和轮廓置信度。候选点只表示视觉安全点，不代表机械可达性。
7. **小规模拼图求解**：对 1--4 块枚举旋转、平移、整边/部分边对齐和接缝方向；用端点误差、边长比例、重叠面积、矩形闭合、面积和尺寸范围做硬约束/评分。
8. **图案连续性评分**：对有效几何接缝两侧做法向灰度带采样，使用归一化互相关或 SSIM 评分；先估计每条边内侧条带的信息量，边界紧挨花纹的边优先比较，纹理弱时降低权重，不用 ORB 单独决定接缝，也不要求红桃、黑桃等图案严格像素级对齐。
9. **质量门控与候选排序**：检查拼图块数、初始轮廓完整位于上半区、轮廓残差、重叠、空洞、目标矩形尺寸和目标轮廓完整位于下半区；几何非唯一或近似等价时由纹理软评分选出最好候选。
10. **结构化输出与题目流程**：只发布 `PuzzleScene`、`PuzzlePlan` 和经映射验证的 `PuzzlePlacement`；基础题、发挥题一和发挥题二动作后均重新扫描复核，发挥题二的花纹内容只在几何候选通过后追加排序证据。

## 4. 方案比较结论

| 子任务 | 首选 | 备选 | 不采用为主链路的方案 |
|---|---|---|---|
| A4 定位 | 固定四角校验 + 四边形几何 | Canny + `approxPolyDP` | 依赖学习模型的页面检测 |
| 拼图块分割 | 任务 1/2 绿色 A4 纸面 Lab 背景反选；任务 3 A4 纸面 Lab 距离 | 白色 HSV 或自适应阈值回退 | YOLO 框直接量测 |
| 顶点 | 直线拟合交点 + 亚像素细化 | `approxPolyDP` 初值 | 检测框角点 |
| 接缝判断 | 边长/端点/重叠硬约束 + ZNCC/SSIM | ORB + RANSAC 辅助 | 纯 ORB 或纯深度网络 |
| 布局求解 | 1--4 块子集 DP/二叉合并 | 受约束穷举 | 端到端布局回归 |
| 运行时 | C++ OpenCV/ROS 2，低频扫描 | TensorRT 只作 ROI 降级检测 | 默认启动 YOLO、Kalman 或 Web 主链路 |

## 5. 必须补齐的验证门槛

使用真实 A4、真实拼图块和目标照明采集代表性数据，覆盖偏亮、偏暗、阴影、轻微反光、不同旋转、相邻不接触、接近接触、轻微失焦和局部遮挡。至少记录：

- A4 重投影误差 P50/P95，目标初值为 P95 ≤ 1.0 mm；
- 拼图块顶点误差 P50/P95，目标初值为 P95 ≤ 2.0 mm；
- 计数与实例分离正确率，代表性集合目标为 100%；
- 完整布局正确率，按 1、2、3、4 块分别统计；
- 感知/复核及首次求解的 Jetson P50/P95 延迟；
- 非唯一几何场景下的花纹排序正确率、拒绝率、重试后恢复率；
- 放置后相邻顶点复核 P95，目标初值为 ≤ 5.0 mm。

在这些数据取得前，不能宣称算法已达到题目验收精度；当前可确认的是架构方向和安全拒绝逻辑。若经典链路在真实样本上不能达到门槛，下一步才对比 YOLO-seg/U-Net 的 ROI 提供能力，并保留几何轮廓和硬约束作为最终量测与验收层。

## 6. 当前实现需要优先核查的点

- `extract_pieces` 目前按中心排序后直接截断到 `max_piece_count`；若噪声候选排在真实块之前，可能丢失真实碎片，应改为按综合质量分数筛选并在数量不确定时拒绝。
- 绿色纸面 Lab 背景反选初值尚未经过真实光照样本验证；若阴影、反光或纸面色差导致前景断裂/粘连，应先用现场像素分布调整 YAML，不得退回猜测轮廓。
- `approxPolyDP` 当前仍是主要顶点来源；达到毫米级验收前应增加边直线拟合、交点细化和轮廓残差字段。
- `orientation_deg` 直接来自 `minAreaRect`，需要统一角度定义、长短边切换和 180/360 度归一化后再用于求解。
- 当前文档和验证记录明确标注真实图像尚未验收；任何现场指标必须由 Jetson 实测日志补充。

## 7. OpenCV GPU 加速十轮迭代

OpenCV CUDA 不能覆盖整条拼图链路：`cv::cuda` 适合矩阵级颜色转换、几何变换、阈值和形态学；`findContours`、多边形顶点细化、接缝候选组合和子集 DP 仍主要是 CPU/OpenCV 标准接口。因此最终采用“GPU 前处理 + CPU 几何/求解”的混合方案，而不是强行全 GPU 化。

| GPU 轮次 | 比较点 | 结论 |
|---|---|---|
| 1 | 整条链路改 CUDA vs 只加速大矩阵阶段 | 只加速大矩阵阶段；轮廓和 DP 全 GPU 化收益不足且接口缺失。 |
| 2 | CPU `warpPerspective` vs `cv::cuda::warpPerspective` | 作为可选 GPU 阶段；先测单帧上传、变换、下载总耗时，低频扫描不满足收益时保留 CPU。 |
| 3 | CPU BGR→HSV vs `cv::cuda::cvtColor` | 推荐 GPU；HSV 是逐像素操作，适合并入一次 GPU 常驻处理。 |
| 4 | CPU `inRange` vs CUDA 范围掩膜 | 推荐先以 CPU 结果为基准，再按实测收益迁移；绿纸和白块必须继续使用独立范围。 |
| 5 | CPU `threshold/inRange` vs 对应 CUDA 算子/自定义 kernel | 推荐 GPU；先确认目标 Jetson OpenCV 构建是否提供对应 API，输出二值 mask 后再下载给 CPU。 |
| 6 | CPU opening/closing vs `cv::cuda::createMorphologyFilter` | 推荐 GPU；固定小核和 1 次迭代时收益有限，但可与前序 mask 保持 GPU 连续处理。 |
| 7 | CPU `distanceTransform` vs GPU 实现 | 暂不作为第一阶段 GPU 化；拾取点只对最多 4 个候选轮廓计算，CPU 成本低，避免引入自定义核维护负担。 |
| 8 | GPU mask 直接做轮廓 vs 下载后 `findContours` | 下载二值 mask 后 CPU `findContours`；这是当前最稳、最可解释的边界。 |
| 9 | GPU 常驻一帧 vs 每算子上传/下载 | 推荐单帧 `GpuMat` 常驻：上传一次，完成 warp→颜色→分割→形态学，下载一次；禁止每个算子单独拷贝。 |
| 10 | GPU 强制启用 vs 运行时能力探测 | 运行时探测 `cv::cuda::getCudaEnabledDeviceCount()`、算子可用性和实际耗时；失败或收益不足自动降级 CPU，结果语义保持一致。 |

### 7.1 最终 GPU/CPU 流水线

1. **CPU**：采集帧、清晰度筛选、A4 四角检测与排序。
2. **GPU（可选）**：上传一次 `GpuMat`，执行 `warpPerspective`、BGR→HSV、绿纸/白块/磁铁各自的 `inRange`、opening/closing。
3. **CPU**：下载最终前景 mask，执行 `findContours`、面积和边长过滤、直线拟合、顶点交点细化、拾取点和质量评分。
4. **CPU**：执行 1--4 块子集 DP、接缝 ZNCC/SSIM、几何质量判断和 `PASS/RETRY/FAIL` 门控。
5. **GPU 可选复用**：若启用图案接缝评分，可将少量 ROI 灰度带批量上传；不得为几个小 ROI 反复创建 CUDA 上下文或产生多次同步拷贝。

### 7.2 GPU 采用门槛

GPU 版本只有在 Jetson 实机同时满足以下条件后才成为默认路径：

- GPU 路径与 CPU 路径在同一输入帧上的 mask、轮廓数量、顶点顺序和布局结果一致；
- 统计上传、GPU 算子、下载和 CPU 后处理的 P50/P95，而不是只报 kernel 时间；
- 端到端单次感知/复核延迟确实低于 CPU 基线，且没有明显增加帧丢失、内存峰值或温度降频；
- CUDA/OpenCV 不可用、上下文初始化失败或 GPU 路径结果质量不达标时，能够自动回退 CPU 并保留相同拒绝逻辑；
- 不把 WSL/x86_64 的 CUDA 或 OpenCV 结果作为 Jetson 验收证据。

当前项目的 CMake 只声明 `core/imgproc/videoio`，尚未声明 `cudaimgproc/cudawarping` 或 CUDA 语言目标；因此 GPU 方案目前是已收敛的设计，不应在未完成 Jetson 依赖、编译和实测前宣称已经启用。

## 8. 轮廓算法十轮迭代

本轮比较对象是“如何从拼图块前景得到可用于毫米级几何求解的轮廓”，不是单纯比较哪一种 API 更快。当前代码对基础题和发挥题一使用绿色 A4 纸面 Lab 背景反选前景，对显式关闭该入口的场景保留白色 HSV 回退，并继续使用 `findContours(RETR_EXTERNAL, CHAIN_APPROX_NONE)`、`approxPolyDP`、图像矩和 `minAreaRect`；下表针对其精度、断裂、粘连和可解释性风险进行收敛。

| 轮次 | 候选算法/参数 | 结论 | 主要原因 |
|---|---|---|---|
| 1 | `connectedComponentsWithStats` vs `findContours` | 连通域用于计数和粗筛，`findContours` 作为最终轮廓 | 连通域提供面积/框，但不保留有序边界点；拼图求解需要顶点序列和边段。 |
| 2 | 灰度/颜色 mask 的外轮廓 vs Canny 边缘轮廓 | 前景 mask 的外轮廓为主，Canny 仅作 A4 或断裂边缘候选 | Canny 易产生双边、断裂和背景纹理边缘；mask 外轮廓天然对应实体区域。 |
| 3 | `RETR_EXTERNAL` vs `RETR_LIST/CCOMP` | 默认 `RETR_EXTERNAL`，孔洞只作质量信号 | 题目不要求把内部纹理当独立碎片；层级轮廓会把图案/噪声引入候选。若检测到异常孔洞则拒绝或重试。 |
| 4 | `CHAIN_APPROX_SIMPLE` vs `CHAIN_APPROX_NONE` | 最终精度路径使用 `CHAIN_APPROX_NONE`，粗筛可用 SIMPLE | NONE 保留边界全部采样点，适合直线拟合和残差；碎片最多 4 块，内存成本可控。 |
| 5 | 单次 `approxPolyDP` vs 多 epsilon 扫描 | `approxPolyDP` 只作顶点初值，epsilon 在配置范围内扫描 | 单一 epsilon 会在锯齿、反光或轻微缺口时丢边/增边；候选需同时满足 3--5 边、面积和边长约束。 |
| 6 | `minAreaRect` 直接代表轮廓 vs 边段直线拟合 | `minAreaRect` 只提供粗方向，最终顶点由边段拟合交点生成 | 旋转矩形会覆盖凹口和不规则切边，不能代表拼图真实外轮廓。 |
| 7 | `HoughLinesP` 单独拟合边 vs 轮廓点 `fitLine`/稳健直线拟合 | 以轮廓点分段后 `fitLine` 为主，Hough 只作断裂边候选 | Hough 投票参数敏感且可能跨越不同边；轮廓点已具备边界归属，便于按多边形顺序拟合。 |
| 8 | 像素角点 vs `cornerSubPix` | 先用多边形/边线交点初始化，再在原灰度边缘上做 `cornerSubPix`（可选） | 直接像素角点量化误差大；亚像素细化只有在焦点、边缘对比和初值质量合格时才启用。 |
| 9 | `convexHull`、凸性强制 vs 保留真实凹轮廓 | 不使用 `convexHull` 修正最终轮廓 | 凸包会填平凹口，破坏拼图接缝和面积；仅用凸性作为 A4 外框筛选条件。 |
| 10 | Watershed/主动轮廓/YOLO-seg vs 经典轮廓主链 | 经典 mask→轮廓→边线为主；Watershed 只处理明确粘连，学习分割只作降级对照 | 当前目标少、背景可控且需要可解释毫米几何；复杂算法需额外标注、调参和 Jetson 实测，不能未经证据替换主链。 |

### 8.1 最终轮廓处理链

1. **前景 mask**：基础题和发挥题一动态采样绿色 A4 纸面 Lab 背景并反选非纸面前景；白色 HSV `inRange` 只作显式关闭背景反选后的回退；随后执行 opening/closing、页面边界和分界线排除。
2. **粗筛**：`connectedComponentsWithStats` 统计连通块数量、面积和外接框；数量不在 1--4 时直接进入重试/失败门控。
3. **边界保留**：对通过粗筛的连通块使用 `findContours(RETR_EXTERNAL, CHAIN_APPROX_NONE)`。
4. **多边形初值**：在多个 `epsilon` 候选上运行 `approxPolyDP`，只保留 3--5 边、面积差、边长和方向合理者。
5. **边段细化**：按照初始顶点把完整轮廓点分配到相邻边，使用稳健 `fitLine` 或加权最小二乘拟合直线，并以相邻直线交点更新顶点。
6. **亚像素可选细化**：当局部梯度、边缘连续性和拟合残差通过门控时运行 `cornerSubPix`；否则保留几何交点并降低置信度。
7. **几何输出**：重新计算有序顶点、面积、中心、方向、边长、轮廓残差、凹陷/孔洞标志和最大内接圆拾取点。
8. **求解输入**：仅把质量门控通过的轮廓送入子集 DP；轮廓不完整、边数异常、重投影误差过大或跨帧不稳定时不得继续求解。

### 8.2 需要避免的实现陷阱

- 不要在轮廓排序后直接截断前 4 个候选；应先按质量分数和空间约束筛选，否则噪声可能挤掉真实碎片。
- 不要用 `convexHull`、`minAreaRect` 或 YOLO 框替代真实拼图轮廓。
- 不要为满足 3--5 边或 20 mm 最小边长而自动删除大钝角顶点、合并两条真实边或重写物理轮廓；候选不可信时应拒绝并重扫。
- 不要把 Canny 双边中的任意一条直接当作实体边界；必须通过前景区域、法向方向和闭合性确认。
- 不要把 `cornerSubPix` 的输出当成必然更准；必须记录梯度、窗口、迭代终止和细化前后残差。
- 轮廓算法的 GPU 化只应放在 mask 和形态学前处理；`findContours`、边线拟合和角点细化继续以 CPU 结果为基准，除非 Jetson 上有等价实现并完成逐帧一致性验证。

### 8.3 轮廓验收指标

- 轮廓 IoU 与人工标注多边形 IoU；
- 顶点到标注边/顶点的 P50、P95 毫米误差；
- 边线拟合 RMS 残差和最大残差；
- 碎片计数准确率、粘连误分率、孔洞/纹理误检率；
- 不同 `epsilon`、光照、轻微失焦和反光条件下的结果稳定性；
- 轮廓阶段自身 P50/P95 延迟，以及 mask 下载到 CPU 后的总端到端延迟。

没有真实标注轮廓和 Jetson 实测前，上述指标只能作为验收门槛，不能写成已达到的结果。
