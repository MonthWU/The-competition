# framework/ —— 避障预扫描方案设计（2027 智能搬运增量）

> 目标：今年相对去年项目**只增加避障能力**，不修改现有视觉/串口/任务代码。
> 设计原则：**只增不改**——新增节点全部放 `framework/`，现有 `obj_detect/`、`qrc_skandier/`、
> `launch/run_all.launch.py`、`obj_serial.py` 等一律不动；新节点 git 独立提交，可随时回滚。

## 1. 背景与规则约束（摘自比赛命题）

- 场地：2400×2400mm，灰色行车道（十字车道宽 400mm），4 个 450×450 淡黄区，2 个启停区（300×300）
- 障碍物：**黑色模拟障碍物 φ50×100mm，数量与位置随机抽签**；比赛可能更换形状（按"黑色几何体"通用识别设计）
- 二维码：每赛场仅 1 个 A4 板（位置随机），读任务码（4 组三位数，如 `134+123+314+231`）
- 任务流程（原任务，本项目不修改）：一键启动 → 读码 → 原料区抓料 → 粗加工放置 → 暂存 → 第二批 → 回启停
- 时间：调试 3min（剩 30s 就位），运行 3min，一键启动仅一次（5s 内）

## 2. 总流程

```
[一键启动]
  → 阶段0 预扫描：斜视摄像头(车顶) 0°/45°/90° 各拍 1 帧（≤5s）
  → 阶段1 识别：YOLOv11(1类 obstacle) 主识别 + CV 黑色分割兜底
  → 阶段2 判定：误差圈(随距离增大) → 命中 17 候选点 → 简化为 13 判定点 → 障碍节点集
  → 阶段3 规划：场地节点图 BFS/A* 避障最短路径 → 串口下发路径指令
  → 阶段4 原任务：按规划路径执行现有 run_all.launch.py（读码→搬运→放置）
```

## 4. 串口分时

- 预扫描/规划阶段：`mission_dispatcher` 独占 ttyS1 下发路径指令
- 原任务阶段：`obj_serial` 独占 ttyS1（原协议不变）
- 两阶段时序隔离，不并发写串口

## 6. 预扫描流程规定（用户定义 2026-08-31）

时序（mission_dispatcher 负责编排，全部为新增节点/新增串口逻辑）：

```
[1] 开启摄像头3（暂定：新 USB 相机，video 设备号待定）
[2] 视觉等待下位机串口指令（暂定指令格式见 serial_protocol.py）
    —— 此阶段需要新增"读串口"能力（原 obj_serial 只写不读）
[3] 收到指令 → 云台转 0° 拍照 → 回传成功指令(0°)
[4] 云台转 45° 拍照 → 回传成功指令(45°)
[5] 云台转 90° 拍照 → 回传成功指令(90°)
[6] obstacle_detector 三帧识别障碍 → road_judge 就近候选点 → MapModel 标记
[7] 地图数字化收尾：把"其余 x 换成 1"——无障碍候选点保持可通行，
    最终 5×5 矩阵只含 1/0（有障碍=0，其余=1）
[8] 通过串口把 5×5 纯 1/0 矩阵传输给下位机（格式见 serial_protocol.py）
[9] 关闭（kill）摄像头3 —— 已确认：地图发送成功后立即关闭（[8]→[9] 连续执行）
[10] 进入原流程（拉起 run_all.launch.py，原任务零改动）
```

关键点：
- **串口方向扩展**：原 obj_serial 只发（上位机→下位机）；预扫描阶段需要
  - 读：下位机 → 上位机（触发指令）
  - 写：成功回传 + 地图矩阵
  - 分时：预扫描阶段由 mission_dispatcher 独占 ttyS1；原任务阶段 obj_serial 独占
- **地图矩阵格式**：25 位 1/0（5×5），下位机据此重建通行地图
- **摄像头3 生命周期**：仅预扫描阶段开启；**地图发送成功后立即关闭**（已确认，不占用 USB 带宽）
