# 标靶二 1080p 圆心精定位

## 最新串口要求：α与(dx,dy)

用户后续要求同时传输三个标靶的偏转角和中心偏差，现改为[当前串口协议](SERIAL_PROTOCOL.md)规定的0x55十字节帧，包含YOLO/OpenCV来源、0.01°定点角度和有符号像素差。|α|超出3°时使用YOLO标靶二中心差，满足条件后用OpenCV精定位；精定位由三个当前圆心实时更新α，超限回退。此前“所有两两连线都<=3°”改为三个中心拟合直线的统一α，仍保留三类唯一、标靶二最近等门控。以下0x54、两两角度与旧实机数值均保留为历史，不代表当前报文或新版本已实机验收。

## 状态与输出

普通物块模式沿用原有YOLO框过滤、最近物块选择及标靶输出。三个有效标靶必须分别为targetOne/targetTwo/targetThree，各一个；中心按x排序，三个两两连线相对画面水平线的角度绝对值均<=3°，且targetTwo唯一最接近图像中心，才触发切换。重合中心、额外重复框、歪折三点及最近距离并列均不触发。

相机由640×360 MJPEG 90fps请求切换为1920×1080 MJPEG 30fps请求：同一采集线程先释放再重新打开设备，核对实际帧尺寸，首帧后重新应用曝光50/gain16/brightness128并丢弃过渡帧，清除旧结果。只保留模型实例，不调用YOLO推理。

触发帧targetTwo中心按config.target_focus.mode_transform映射为新图像初始种子。默认[1,1,0,0]假定两种模式同视场、无相对裁剪，尚需实机核对；可配置归一化x/y缩放和平移。C++ OpenCV在种子附近有界灰度ROI内寻找圆，按圆心到种子的距离选最近候选；后续用上次真实圆心更新种子，不使用新的YOLO框。未找到圆的帧没有有效偏差，不重发上一帧结果。

输出`dx=round(circle_x-width/2)`、`dy=round(circle_y-height/2)`，单位为1080p像素，向右/下为正。准星采用像素坐标(960,540)。本轮未加入自动成功判定或新的卡尔曼滤波。

## 下位机接口

- 新精定位帧：`FF 54 dx_lo dx_hi dy_lo dy_hi FE`，dx/dy均为有符号int16、小端补码。例(-10,+20)：`FF 54 F6 FF 14 00 FE`。
- 独立类型0x54避免与原`FF 52 x_lo x_hi y_lo y_hi FE`标靶二绝对坐标混淆。原颜色物块0x41–0x46和普通标靶0x51–0x53保持原含义。
- 接收端须按固定7字节解帧，不能遇到载荷中的FF或FE就提前结束；负数补码高字节通常为FF。
- MCU在精定位完成后发送ASCII`[align_done]`，或以`[align_cancel]`取消。两者恢复普通模式。MCU固件须实现新类型及结束指令；本轮不修改下位机工程，不宣称其已解析或闭环通过。
- 无圆持续1.5秒或精定位总时长30秒会退出并恢复YOLO，属于失败保护，不视为完成对准。这些阈值可配置。
- 退出后先等待触发条件消失，再允许下一次触发，避免相同画面反复切换；结束命令后的旧精定位帧由应用层抑制。

## 配置与构建

target_focus位于config/system.json；模板默认禁用，config/board.json启用并使用确认的板端设备，config/board-object.json直接进入物块阶段。两者使用当前实机模型及正确类名顺序：red1、yellow1、green1、black1、blue1、blue2、targetOne、targetTwo、targetThree。

核心实现native/target_focus.cpp，经scripts/build_focus.sh编译为native/lib/libcar26_focus.so。不从其他项目复制二进制库。C++调用基于[OpenCV官方HoughCircles说明](https://docs.opencv.org/4.x/d4/d70/tutorial_hough_circle.html)，采用灰度、模糊及有界圆半径。圆检测阈值和搜索半径尚需现场图像调参，不能把人工圆测试当成真实标靶精度验收。

## 验证边界

人工框验证角度、三类别唯一性、距离并列、种子坐标与有符号协议；假相机验证640×360→1080p→恢复、精定位期间YOLO调用次数为0、不发送丢失圆的旧偏差及退出后不立即重触发。板端仅进行编译、配置/文件检查及人工图像算法测试。未自动打开相机、UART或运行真实识别链路。
