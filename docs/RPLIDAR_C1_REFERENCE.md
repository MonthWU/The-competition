## 2. 测量能力与使用边界

| 项目 | 厂商给定值 | 来源 |
| --- | --- | --- |
| 白色目标量程 | 0.05-12m，70% 反射率 | 规格书 p8 |
| 黑色目标量程 | 0.05-6m，10% 反射率 | 规格书 p8 |
| 采样频率 | 5000 次/秒（5kHz） | 规格书 p8 |
| 扫描频率 | 8-12Hz，典型 10Hz | 规格书 p8 |
| 角度分辨率 | 典型 0.72° | 规格书 p8 |
| 测距精度 | ±30mm；测试环境 25°C，目标反射率 10%-90% | 规格书 p8 |
| 俯仰角 | 0°-1.5°，可按需定制 | 规格书 p8 |
| 防护与抗环境光 | IP54；40,000lux | 规格书 p8 |
| 激光等级 | Class 1，典型波长 905nm | 规格书 p6、p9 |
| 温度 | 启动温度下限 0°C；工作 -10 至 40°C；存储 -20 至 60°C | 规格书 p13（C1M1） |
| 预热 | 开启扫描并转动约 2 分钟后，测距精度达到最佳水平 | 使用手册 p13 |

目标距离小于 0.05m 或大于 12m 时即使有输出，也不能按规格精度使用；黑色目标另受 6m 量程限制。低反射、过高反射、光学窗遮挡和供电不足均需纳入异常判断，不能把无有效回波直接判为无障碍。

按典型参数推算：10Hz 时每圈约 500 点、周期约 100ms，0.72° 在 1m 距离对应约 12.6mm 的横向采样间隔。这些是几何与时序估算，**不是定位精度，也不是完整链路延迟**。障碍检测需结合目标宽度、距离、安装高度和多帧一致性确定阈值。

| 电源纹波 | 最大 150mV | 规格书 p11（C1M1） |

直接 UART 接入时交叉连接 TX/RX，并共地；5V 是供电电压，不能作为串口信号电平。连接器方向以原始图和实物为准，不从线色表推断针脚编号。供电设计需为启动电流留余量，不能用 260mA 工作电流选电源；在雷达端测量压降与纹波。规格书 p11 建议正常工作时雷达接口电压大于 5V，同时仍需满足 5.2V 上限。

安装时以测距核心旋转中心定义外参，保证光学窗口不被车体、支架或线缆遮挡。固定螺钉的 4mm 限制是进入本体的深度，不是整颗螺钉长度；底板厚度需计入选型。

## 4. 电机控制及资料不一致

- 规格书 p13：C1 有内部闭环电机控制，通过串口指令设置转速；电机不能单独启动或停止，需用相应扫描命令控制。
- 使用手册 p4、p11：仍有 PWM 和 MOTOCTL 的描述，但同页接口图和表没有定义 MOTOCTL 接线。
- 项目后续接入以 **C1 专用规格书的扫描命令控制方式** 为依据，不据手册文字自行接出 PWM/MOTOCTL。若实物版本另有接口，先核对铭牌及厂家确认。
- 协议 p32 的通用 MOTOR_SPEED_CTRL 命令为 `0xA8`，负载是小端 u16 RPM；通用描述包含 RPM=0 进入空闲。此描述不证明 C1 支持独立电机启停，应通过适配 C1 的 SDK 处理型号差异。

## 5. 协议速查

来源：协议 p4-p8、p12-p15、p19-p26、p28-p32。协议是二进制小端通讯，不能与项目 MCU 的文本帧混用。

请求从 `A5` 开始。无负载请求为 `A5 Cmd`；有负载请求为 `A5 Cmd Len Payload Checksum`，校验值为前面所有请求字节的异或。一个请求须在 5 秒内发送完整。

起始应答描述符为 7 字节：`A5 5A`、4 字节小端长度/模式字段、1 字节数据类型。长度占低 30 位，应答模式占高 2 位（0 单次、1 多次）；描述符在一次扫描请求后只发送一次，后续数据包格式取决于应答类型。

| 命令 | 请求或命令值 | 应答与注意事项 |
| --- | --- | --- |
| STOP | `A5 25` | 无应答；下一请求前按 p13 等待至少 10ms |
| RESET | `A5 40` | 无应答；下一请求前按 p13 等待至少 500ms |
| GET_INFO | `A5 50` | 类型 `0x04`，20 字节；包含型号、固件、硬件和 16 字节序列号 |
| GET_HEALTH | `A5 52` | 类型 `0x06`，3 字节；状态 0 良好、1 警告、2 错误/保护停机，随后是小端 u16 错误码 |
| SCAN | `A5 20` | 描述符 `A5 5A 05 00 00 40 81`；每点 5 字节 Standard 数据 |
| EXPRESS_SCAN | `0x82`，必须带 5 字节负载 | 工作模式 ID 加 4 个保留零字节；模式与返回格式需查询设备 |
| GET_SAMPLERATE | `A5 59` | 类型 `0x15`，4 字节；标准/高速采样时间各为 u16 微秒 |
| GET_LIDAR_CONF | `0x84`，带负载 | 类型 `0x20`，长度可变；返回设备模式与配置 |
| MOTOR_SPEED_CTRL | `0xA8`，带 2 字节 RPM 负载 | 单位是 RPM；10Hz 对应 600RPM，不能将数值 10 当成 10Hz 下发 |

GET_INFO 的首字节高 4 位为 MajorModel、低 4 位为 SubModel；C1 的 MajorModel 为 4（协议 p24-p25），不要把完整首字节直接与 4 比较。

Standard 每点 5 字节：S 与其反码必须互补，C 校验位固定为 1；角度为 `angle_q6 / 64.0` 度，距离为 `distance_q2 / 4.0` 毫米，距离 0 为无效点。S=1 表示新一圈。此格式没有可统一套用到所有模式的完整字节校验和。

DenseBoost 的典型应答类型为 `0x85`，包长 84 字节，每包 40 个距离点；距离直接为毫米，0 为无效点。首两字节的高半字节同步标志分别为 A、5，低半字节组成校验和；异或校验从包偏移 +2 开始。角度需结合相邻包的起始角插值，必须处理跨 360° 和丢包重同步。协议 p24 的 DenseBoost S 标志也用于解析重启，不能直接沿用 Standard 的每圈起点判断。

协议 p11 明确：**C1 的 Standard 与 DenseBoost 均为 5000 次/秒、12m 最大量程**；模式切换不会让 C1 达到 S 系列的 16000/32000 次/秒。12m 同时仍受目标反射率条件限制。

模式查询字段包括 `0x70`（模式数量，ID 为 0 到数量-1）、`0x71`（采样用时）、`0x74`（最大距离，q8 米）、`0x75`（应答类型）、`0x7C`（推荐模式 ID）、`0x7F`（模式名称）。以设备查询和 SDK 解析为准，不能硬编码 DenseBoost 模式 ID 或复用 S 系列参数。

协议自身存在可见不一致：p19 的 EXPRESS_SCAN 示例尾字节固定为 `22`，但 p6 的异或规则要求随模式 M 变化（其余负载为 0 时是 `22 XOR M`）；p33 流程图末尾标 1ms，而 p13 STOP 专节要求至少 10ms。后续实现使用通用校验规则和 STOP 专节等待时间，不机械复制示例。

协议 p34 的原始公式为 `RPM = (1 / ΔT) × 60`，其中 ΔT 是一圈时间；若单位为秒，即 `60 / ΔT`。文本提取会丢失分式版式，不能误读为 `1 / (ΔT × 60)`；且 DenseBoost 的重同步 S 标志不能直接用作每圈计时依据。

## 6. 项目接入建议与待确认事项

协议 p3、p11、p19 推荐使用厂商 [rplidar_sdk](https://github.com/Slamtec/rplidar_sdk) 的封装。本次新项目依照协议直接实现 C1 Standard UART 解析，代码见 `car26/radar/`；没有安装 SDK/ROS 驱动。直接解析的硬件兼容性仍待实测；若将来采用 SDK，需核对 C1 和实际 ARM64 平台支持并锁定版本。

原始 C1 坐标：旋转中心为原点，正前方为 +x、右侧为 +y，角度顺时针增大（规格书 p10）。若项目采用车体 +x 前、+y 左、+z 上的坐标，则在安装朝向一致时原始极坐标可按 `x = r*cos(theta)`、`y = -r*sin(theta)` 转换；r 需从毫米转为米，再叠加安装平移与偏航外参。这是基于两套坐标定义的推导，实际 ROS 驱动可能已做转换，接入前必须核对，避免重复反向。

新项目由雷达模块负责设备 I/O、健康状态、扫描与聚类，地图映射层负责标定定位，通信模块负责既有 MCU 地图帧发送。雷达串口与 MCU 串口分别配置和管理，不把雷达二进制协议接入 MCU 命令解析器；没有独立雷达 ROS 节点。

待后续接入时确认：

- 实物型号/固件/序列号；USB 转接或直接 TTL UART；稳定设备标识，不能先假定 `/dev/ttyUSB0`。
- 实测启动供电、雷达端电压/纹波、冷启动温度与扫描稳定性。
- 安装高度、实际俯仰角、车体遮挡区域、零角朝向和车体外参。
- 模型/固件查询结果、Standard 扫描描述符、单位、角度方向与时间戳语义；若后续使用 ROS 驱动，再核对话题和 frame_id。
- 雷达替代或参与障碍预扫描的具体范围，以及与现有起点、地图和 MCU 流程的接口。
- 现场障碍的反射率、量程、最小尺寸、误检漏检、断流处理与端到端时延。

新项目已完成源码及人工数据协议测试；没有实机供电、扫描数据或障碍识别验收证据。运行验证仍按 [database.md](database.md) 由用户执行，构建与启动登记按 [deployment.md](deployment.md) 执行。
