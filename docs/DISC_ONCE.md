## 触发与执行

上位机Mission必须为OBJECT，且相机真实recognition_mode必须为block（0x61）。MCU发送五字节原始确认：

```text
5B 61 2C 01 5D
```

0x61及BOOL均为原始单字节，不是字符串"0x61"或字符"1"。通信模块仍更新peer_states，并额外提交disc_once，由主线程检查Mission，再由相机在锁内检查真实功能状态。0x61退出通知、0x60/0x62通知和其它命令不触发；二维码、标靶精定位、关闭或功能禁用状态的确认被忽略，不留到下一阶段执行。

确认只登记一个有界请求，在之后开始read的每张完整采集原图上持续运行既有C++圆盘算法。未检出或偏差无效时保留请求，下一帧继续检测；首次成功取得有效圆心偏差才结束搜索，发布一个完成事件，发送一次后停止。YOLO继续逐帧处理缩小图。没有请求时不加载圆盘库，也不执行检测；无需等待两轴达到5像素。搜索和待发送结果尚未完成时的重复确认合并，不建立无界队列。成功后收到新确认可再次开始搜索。请求及测量在退出block、关闭相机时清除；搜索期间保持物料识别模式，不自动进入标靶模式。

单槽事件保存本次帧的序号、单调时间、请求编号和偏差，不受后续普通YOLO帧覆盖。主线程取出后按原有sensor_timeout_s检查新鲜度，再由唯一UART所有者发送一次；请求编号仅在进程内去重，不添加到线上报文。

## 回复：固定9字节

用户已确认下列编码，两个英文逗号均实际发送：

```text
5B 61 2C dx_lo dx_hi 2C dy_lo dy_hi 5D
```

| 偏移 | 内容 |
| --- | --- |
| 0 | 0x5B，帧头 |
| 1 | 0x61，圆盘偏差回复 |
| 2 | 0x2C，逗号 |
| 3～4 | dx，有符号int16小端 |
| 5 | 0x2C，逗号 |
| 6～7 | dy，有符号int16小端 |
| 8 | 0x5D，帧尾 |

dx/dy为圆心减去本次原图(width/2,height/2)，右和下为正，取整后范围[-32768,32767]。默认720p图像中心为(640,360)，不使用640×360的YOLO像素，也不隐式做倍数换算。例dx=-12、dy=8：

```text
5B 61 2C F4 FF 2C 08 00 5D
```

未检出、非有限值或int16范围外不发偏差包，持续搜索，不以(0,0)表示失败；实际有效圆心位于中心时可发送(0,0)。不设置搜索超时，直到检出、退出物料阶段或关闭应用；设备或原生库异常仍走现有失败及资源清理流程，不发送旧结果。没有新增失败类型码、ACK或串口自动重传。

0x61仍存在五字节状态通知，与本九字节回复共用类型字节。MCU必须区分两种布局，不能仅凭0x61决定固定读5字节，不能遇到偏差载荷中的0x5B/0x5D或0x2C就截断。尤其dx_hi=0x5D且dx_lo为00/01时，九字节回复的前五字节与状态包相同：接收端须保留缓冲并结合九字节结构及后续数据判别；当前用户指定格式没有长度或转义，单独五字节前缀不能证明它是状态包。视觉端接收解析器仅解析MCU命令，不作为MCU测量接收器使用。

HMI的camera.disc_state为waiting_request、searching、measured、inactive或disabled；disc_processed_frames为本实例真实调用次数。未检出时显示searching并清空无效测量；成功由disc_reply事件保留记录。旧DiscAlignment容差工具保留兼容测试，但正式CameraModule不再调用它；tolerance_px不是触发或发送条件。独立圆盘诊断入口仍按手动运行目的工作。
