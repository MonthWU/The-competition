# 实际赛场观测与标定约束

来源：用户2026-11-07补充；这是现场规则和设备条件陈述，不是本次实机验收结果。结构化记录见[simulation/field_constraints.json](../simulation/field_constraints.json)，该文件目前仅保存要求，不由估计器读取。

## 二维码板不是固定坐标地标

用户已确认：“上下”是沿地图边缘的平面位移，板下沿仍接地，不是离地高度变化。具体允许区间与误差上限尚未提供，不猜测摆放范围。仿真继续保持210毫米板高、下沿0、中心105毫米；现有固定沿边位置只是测试预设，尚未依据未知范围增加随机平移。

当前代码中的板端点(2.3985,1.0515)/(2.3985,1.3485)米属于固定仿真场景预设，不是实际比赛板子的已知准确位置。沿边摆放位置未测量时，单块板观测和蓝区范围可能有多组小车/板位置解释，不能把其中一组直接当作唯一比赛坐标。若仍拿固定板坐标做锚点，板位置的偏差会传入车体坐标。

后续实车应现场测量实际板位姿，或者将板位姿作为有范围约束的未知量，与其他独立已知的固定几何共同估计。下位机起点类别只限制搜索蓝区，不提供精确车体坐标，也不能消除所有板位/车位歧义。未明确具体摆放范围前，不填造数值门限。

当前C++初始化器仍是有限板段匹配固定端点的基线，尚未实现板位置范围搜索、联合估计或误差传播。日常启动保持`anchor_geometry_confirmed=false`；显示窗口按蓝区预设对齐，并不表示已确认真实比赛坐标。

## 实际雷达可见性

用户确认工作扫描高度应能扫到二维码板、地面放置的物块和轮子。它们都应被当作可能产生回波的几何物体，而地面印刷标靶区域本身不是竖直障碍。实际回波仍取决于无遮挡、量程、反射条件和角度采样，不能要求每个位置每帧都完整观测到所有目标。

17.618526毫米是现有CAD光窗假设推导的仿真参考扫描高度，不是用户本次给出的实测离地高度。“能扫到几类物体”不足以反推出唯一高度，不据此擅自改雷达Z值。

用户最新明确要求仿真恢复本车轮子回波，替代此前完全关闭车体遮挡的测试默认值。简化车体SLAM入口Auto现在采用wheels：四个轮子在GPU雷达中可见，其他简化车体仍保持此前测试可见性设置，雷达壳体不挡自身扫描。原始扫描真实产生轮子回波，自有前端继续用仅含局部几何的掩码过滤匹配的自体回波，再交给SLAM；物理遮挡仍然存在，不能过滤轮子后再凭空补出其后方障碍。Disabled保留为对照，Model恢复全部模型遮挡，详细CAD因轮子与车体合为网格，Auto使用Model。

现有未标定CAD预设下，近处圆柱在轮子的阴影中，因此恢复轮子后不再保证静止起点同时看到两个圆柱。后续按雷达实际伸出后的测量外参重新生成场景与遮挡掩码，再检查两障碍可见性；本次不擅自移动雷达来满足期望结果。

当前场景中的物料主要位于转盘，圆柱是障碍物；本次没有凭空增加地面物块、猜测其位置或宣称已验证地面物块检测。

## 雷达伸出车体后的外参

用户确认实际雷达会伸出车体，位置存在误差，后续实测标定。当前CAD位置只代表仿真参考安装状态，不代表伸出后的真实位置；实际伸出量、末端姿态及误差范围均未填写。

标定应在最终伸出并锁定的状态进行，记录车体参考原点与坐标轴、雷达扫描中心x/y偏移和离地高度、扫描零角、倒装后的角度方向，以及安装倾斜和重复伸出误差。陀螺仪还需核对Z轴正方向、相对零位与时间对齐，不能把上电零角当作地图绝对朝向。

实际转角外参也必须进入扫描坐标转换和TF。当前仿真`.robot.json`只传三维平移，前端雷达yaw假设为0，尚不能用“填写平移”代替完整的伸出安装标定。未来扩展接口时，需要同时更新C++前端、静态TF、车体遮挡计算和仿真生成器，并用独立位置/朝向验证。

标定完成前，`config/system.json`中的`extrinsic_calibrated=false`与日常板几何确认关闭状态保持原值；不因写了要求文档就解除下位机坐标输出门控。
