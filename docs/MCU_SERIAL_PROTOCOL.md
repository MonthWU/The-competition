## 1. 串口和通用编码

| 项目 | 约定 |
| --- | --- |
| 波特率 | 115200 bit/s |
| 数据格式 | 8位数据，无奇偶校验，1位停止位，即8N1 |
| 流控 | 不启用软件流控、RTS/CTS或DSR/DTR流控 |
| 视觉端当前设备 | `/dev/ttyS2`，仅说明视觉配置，不代表MCU的串口编号 |
| 帧头 | 一个原始字节0x5B，即字符`[` |
| 帧尾 | 一个原始字节0x5D，即字符`]` |
| 多字节整数 | 小端：低字节在前，高字节在后 |
| 有符号整数 | int16补码，范围-32768～32767 |
| 通用校验 | 当前二进制报文没有CRC、校验和、序号或时间戳；兼容ASCII地图包另有异或校验 |
| 通用确认 | 当前测量、二维码和状态包没有通用ACK或重传机制 |

下文十六进制示例中的空格只是排版，**不发送空格字符**。例如二维码类型码0x70在线上发送一个字节`70`，不是字符串`"0x70"`。状态包及新增圆盘0x61偏差回复明确使用逗号；其他二进制包的字段之间没有逗号。保留的ASCII命令和地图包另行说明。

“视觉→下位机”指视觉发送、MCU接收；反向则相反。状态通知允许双向发送。

## 2. 报文总表

| 报文 | 方向 | 线上格式 | 总长度 |
| --- | --- | --- | --- |
| 圆盘单次偏差0x61 | 视觉→下位机 | `5B 61 2C dx_lo dx_hi 2C dy_lo dy_hi 5D` | 9字节 |
| 标靶姿态0x72 | 视觉→下位机 | `5B 72 source alpha_lo alpha_hi dx_lo dx_hi dy_lo dy_hi 5D` | 10字节 |

`{…}×num`表示重复num条记录，不发送花括号或乘号。

## 3. 物块合并包0x71

```text
5B 71 num class1 dx1_lo dx1_hi dy1_lo dy1_hi ... 5D
```

num表示**本帧发送了几种物块**，不是累计数量、框数、数据长度或字节数。num为uint8，合法范围0～6。每种物块仅一条记录，各类合在同一个包内发送。

| 偏移 | 字段 | 类型和说明 |
| --- | --- | --- |
| 0 | 帧头 | 0x5B |
| 1 | 报文类型 | 0x71 |
| 2 | num | uint8，0～6种 |
| 3+5×i | class | 第i条物块的类别码，i从0开始 |
| 4+5×i～5+5×i | dx | int16小端，检测框中心相对当前图像中心的水平偏差 |
| 6+5×i～7+5×i | dy | int16小端，检测框中心相对当前图像中心的垂直偏差 |
| 3+5×num | 帧尾 | 0x5D |

类别表：

| 类别码 | 模型类别名 | 物块 | 模型输出索引（0起） |
| --- | --- | --- | --- |
| 0x41 | redblock | 红色 | 0 |
| 0x42 | blackblock | 黑色 | 3 |
| 0x43 | greenblock | 绿色 | 2 |
| 0x44 | yellowblock | 黄色 | 1 |
| 0x45 | lightblueblock | 浅蓝 | 4 |
| 0x46 | darkblueblock | 深蓝 | 5 |

类别码是串口语义编号，不是模型输出索引。业务类别目录`assets/models/classes.name`顺序为（不作为当前bin的输出索引）：

```text
yellowblock
redblock
lightblueblock
greenblock
targetTwo
blackblock
darkblueblock
targetThree
targetOne
```

当前bin通过assets/models/yolo11_x5.classes.json绑定输出索引。targetOne、targetTwo、targetThree分别为6、7、8；标靶仍使用统一0x72姿态包，不把这些模型索引作为新的物块类别码发送。完整索引及模型SHA256见MODEL_CLASS_MAPPING.md。

每条记录只含**类别、dx、dy**，不含框四角、宽高、置信度、角度或source。dx/dy是框中心的偏差，不是框中心的绝对坐标：

```text
dx = round(框中心x - 当前处理图宽度/2)
dy = round(框中心y - 当前处理图高度/2)
```

向右为正、向下为正。当前默认YOLO处理图640×360，偏差原点为(320,180)；平时相机实际采集640×360；定位阶段切720p时，物块YOLO仍使用640×360处理图像素，不隐式乘2。若后续修改处理图尺寸，双方需同步像素尺度。

视觉会发送所有通过检测过滤及显式物块ROI的有效类别，不再只选最近一种。出现同类重复候选时仅取ROI内最高置信度一条；相同置信度保留先出现者。各条记录顺序不保证固定，下位机必须按class识别类别。每包按当前帧更新，未出现的类别不能继续视为本帧有效。

例：本帧有2种物块，redblock的dx=-320、dy=-180，darkblueblock的dx=319、dy=179：

```text
5B 71 02 41 C0 FE 4C FF 46 3F 01 B3 00 5D
```

这个包14字节，即4+5×2。六种物块全有时为34字节。

无有效物块时仍发送4字节空包，下位机据此清空当前物块有效集合：

```text
5B 71 00 5D
```

进入标靶精定位时YOLO暂停，此时不发送物块包，也不发送num=0来冒充完成了一次空检测。

## 4. 标靶姿态包0x72

```text
5B 72 source alpha_lo alpha_hi dx_lo dx_hi dy_lo dy_hi 5D
```

| 偏移 | 字段 | 类型和含义 |
| --- | --- | --- |
| 0 | 帧头 | 0x5B |
| 1 | 报文类型 | 0x72 |
| 2 | source | uint8：0=YOLO粗定位，1=OpenCV圆心精定位 |
| 3～4 | alpha | int16小端，单位0.01°，解码后除以100 |
| 5～6 | dx | int16小端，标靶二中心相对当前图像中心的水平偏差，右正 |
| 7～8 | dy | int16小端，标靶二中心相对当前图像中心的垂直偏差，下正 |
| 9 | 帧尾 | 0x5D |

alpha由当前三个标靶中心拟合得到，范围[-90°,90°)，线上整数范围-9000～8999。图像x向右、y向下，连线向右下倾斜为正。它是标靶连线的图像偏角，不是新增的车体航向测量。

两种来源的默认尺度：

| source | 用于测量的图像 | dx/dy原点 |
| --- | --- | --- |
| 0 | YOLO处理图640×360 | (320,180) |
| 1 | 标靶模式采集图1280×720 | (640,360) |

两来源都使用自身图像原生像素差，不隐式换算。包内没有宽高字段；后续更改分辨率时必须同步MCU的尺度。当前低分辨率YOLO采集640×360，标靶精定位采集1280×720。

YOLO识别三个唯一且几何有效的标靶后可上报source=0；收到原始5B 62 2C 01 5D并有最近1秒内有效的三标靶快照时，切720p进入source=1精定位。精定位期间暂停YOLO，用当前三个圆心重新计算alpha和标靶二中心偏差。缺少有效测量时不发旧标靶包，不以全零包代替“无效”。

例1：source=0，alpha=-12.34°，dx=-320，dy=180：

```text
5B 72 00 2E FB C0 FE B4 00 5D
```

例2：source=1，alpha=1.25°，dx=59，dy=-138：

```text
5B 72 01 7D 00 3B 00 76 FF 5D
```

当前alpha超出阈值、连续丢圆1.5秒、精定位总时长达到30秒，或收到结束/取消命令，会按现有逻辑退出精定位、恢复物块/YOLO模式。发送频率随有效检测帧变化，没有固定串口上报频率。

## 5. 二维码包0x70

```text
5B 70 UTF-8原文 5D
```

原文必须非空，保留UTF-8内容、空格和换行；不强制数字、分组数或早期任务码规则。原文长度按UTF-8字节数计算，不按字符数计算。当前没有长度字段、结束零字节、CRC或转义。

例：原文为`123`，线上实际字节为：

```text
5B 70 31 32 33 5D
```

视觉成功扫码后连续发送相同包4次，随后flush，再关闭二维码相机并打开物块相机。MCU不需要发送ACK才能让视觉完成这个流程；4次发送不等于4个独立任务，下位机业务应对重复结果做幂等处理。没有约定4次之间的固定时间间隔。

**已确认的分帧规则：合法二维码原文一定不包含字符`]`。**视觉解码、任务交接和编码都会拒绝含]的内容，因此MCU识别到0x70后读取原文字节，首个0x5D就是该包帧尾。正文允许包含`[`（0x5B），此时不能重新起帧。原文保持UTF-8、空格和换行，不加长度、转义或内容改写。

## 6. 双向状态交流

```text
5B Flagnum 2C BOOL 5D
```

| 偏移 | 字段 | 约定 |
| --- | --- | --- |
| 0 | 帧头 | 0x5B |
| 1 | Flagnum | 0x60=二维码，0x61=物块，0x62=标靶 |
| 2 | 英文逗号 | 原始字节0x2C |
| 3 | BOOL | 原始0x01=进入，原始0x00=退出 |
| 4 | 帧尾 | 0x5D |

BOOL不是ASCII字符'0'/'1'，也不是字符串true/false。完整例子：

| 含义 | 实际字节 |
| --- | --- |
| 进入二维码识别 | `5B 60 2C 01 5D` |
| 退出二维码识别 | `5B 60 2C 00 5D` |
| 进入物料转盘识别 | `5B 61 2C 01 5D` |
| 退出物料转盘识别 | `5B 61 2C 00 5D` |
| 进入标靶识别 | `5B 62 2C 01 5D` |
| 退出标靶识别 | `5B 62 2C 00 5D` |

双方分别维护“本机状态”和“对端报告的状态”，每个Flagnum独立进入、退出。可同时存在多个有效状态，不能收到0x62进入就自动清掉0x61。退出某个Flag只清除该Flag，普通状态重复通知保持幂等；0x61/0x62进入请求在忙时合并，空闲时新收到进入帧可提交新请求。当前仅定义0x60/0x61/0x62，其他Flagnum或非法BOOL不接受。

**请求例外：**0x61进入在物料阶段请求圆盘定位；0x62进入在物料阶段且有新鲜三标靶快照时请求标靶精定位。0x62退出仍只记录，不能代替align_done/align_cancel。其它通知只更新对端状态，不改变Mission；无新增ACK。

视觉当前实际功能互斥，扫码启动时先通知0x60进入，扫码发送完成后关闭QR相机通知0x60退出，再进入物块；随后通常为：0x61进入 → 0x61退出 → 0x62进入 → 0x62退出 → 0x61进入。0x61功能运行YOLO粗定位并按0x61确认进行圆盘定位；0x62功能指按MCU进入帧触发的圆心精定位。相同分辨率下切算法也会通知状态。

进入通知表示已进入识别功能，不代表已经取得有效测量；模式切换稳定帧期间可能尚无测量包。正常关闭相机后会发送退出；异常断线、进程被强制结束或写入失败时不保证退出包送达。当前没有重连状态握手、心跳、ACK或重传约定，MCU应独立管理测量新鲜度，不能把“暂时没包”直接等同于“收到退出”。

## 7. 下位机发送的控制命令

以下都是完整ASCII文本，包含左右方括号，不添加CR/LF。不是0x72/0x71/0x70二进制报文。

| 命令 | 实际十六进制 | 生效场景 |
| --- | --- | --- |
| `[align_done]` | `5B 61 6C 69 67 6E 5F 64 6F 6E 65 5D` | OBJECT阶段请求结束精定位、恢复YOLO |
| `[align_cancel]` | `5B 61 6C 69 67 6E 5F 63 61 6E 63 65 6C 5D` | OBJECT阶段请求取消精定位、恢复YOLO |
| `[4]` | `5B 34 5D` | legacy full入口等待起点时选择起点4 |
| `[24]` | `5B 32 34 5D` | legacy full入口等待起点时选择起点24 |
| `[skip]` | `5B 73 6B 69 70 5D` | legacy full入口等待起点时跳过预扫描进入扫码 |
| `[shot]` | `5B 73 68 6F 74 5D` | legacy full入口等待扫描触发时，启动一次预扫描 |

当前默认无雷达入口直接扫码后进入物块阶段，独立物块入口直接进入OBJECT；这些入口不等待[4]/[24]/[shot]，不能用这些命令强行跳转。起点未标定、命令不在对应阶段或已经超时时不视为成功，不保证ACK。未知命令不触发任务操作。

align_done/align_cancel没有专门的ACK报文，也没有携带偏差数据；正常切换可观察0x62退出、0x61进入及后续新测量。不要将[ack]当成这些命令的通用确认。

视觉接收命令支持分片、连续多个包及噪声后重新找`[`，接收帧缓冲默认最大64字节（包含方括号），超长或非法状态包丢弃。下位机应遵循本表的准确命令拼写。

## 8. 保留的预扫描ACK与地图

本节是legacy full流程兼容接口；当前无雷达入口及独立物块入口不主动执行该预扫描流程。没有新增给MCU的路线执行或车辆运动报文。

ACK为5字节ASCII文本：

```text
[ack]
5B 61 63 6B 5D
```

合法且已标定起点的[4]/[24]被接受后发送一次[ack]；一次扫描完成后再发送[ack]。通常三次扫描对应0°、45°、90°三个阶段，收到每次完成ACK后下位机再安排下一次[shot]。[ack]表示对应流程步骤的确认，不是所有包的可靠传输确认；失败情况下可能没有最终地图。

地图是带空格的ASCII字符串：

```text
[count id1 id2 ... check]
```

count和id用十进制文本；字段之间有一个ASCII空格0x20。check为两位大写十六进制文本，数值等于`count XOR id1 XOR id2 ...`，对整数做异或，不对ASCII字节做异或。id去重后升序排列，编码接口支持0～3个，合法id为：1、3、5、7、9、11、12、13、15、17、19、21、23。当前full运行链路三次扫描结束后上报票选的一处障碍编号。

| 内容 | 字符串 | 实际字节 |
| --- | --- | --- |
| 1处，编号13，校验1 XOR 13=0x0C | `[1 13 0C]` | `5B 31 20 31 33 20 30 43 5D` |
| 2处，编号1和3，校验2 XOR 1 XOR 3=0 | `[2 1 3 00]` | `5B 32 20 31 20 33 20 30 30 5D` |
| 0处，校验0 | `[0 00]` | `5B 30 20 30 30 5D` |

## 9. MCU接收实现要点

UART一次接收、DMA完成或空闲中断可能只给出半包，也可能给出几个连在一起的包。应将字节写入接收缓存后连续解析，不能假定一次中断就是一帧。

1. 找到0x5B，读取下一字节分派。
2. 类型0x72：等待10字节，检查第9偏移为0x5D，校验source与字段范围。
3. 类型0x71：先读num，要求0～6；等待4+5×num字节，检查末字节0x5D，并校验类别码合法且不重复。
4. 第二字节0x60/0x61/0x62：等待5字节，检查偏移2为0x2C、偏移3为00/01、偏移4为0x5D。
5. 类型0x70：按第5节读取至首个0x5D；正文不含]，但正文中的0x5B必须保留，不重新起帧。
6. `[ack]`和地图按各自ASCII语法识别，不当成0x72～0x70数据包。

二进制数值中可能出现0x5B或0x5D，应始终按字段长度处理。下面的例子使用source=1、alpha=0、dx=23899（0x5D5B）、dy=23389（0x5B5D）；这些偏差用于编码边界验证，并非当前默认画面可观测范围：

```text
5B 72 01 00 00 5B 5D 5D 5B 5D
```

它是一个完整10字节标靶包，内部的5B/5D不能当新帧头或提前帧尾。接收超时和数据失效阈值需要下位机按业务制定，当前协议没有规定这些时间；链路故障不能靠沿用旧坐标掩盖。

解码int16时，先组合小端uint16，再按补码解释；不能用无符号变量直接驱动控制量。例如`C0 FE`为-320，`4C FF`为-180，`3B 00`为59。
