# 物块相机有界双缓冲

2026-11-24最新本地规则（尚未部署）：用户确认平时实际采集640×360，YOLO仍补边至640×640；收到原始5B 61 2C 01 5D后切1280×720搜索圆盘，检出后只产生一次既定9字节回复并恢复640×360。收到原始5B 62 2C 01 5D后，冻结当时最近一次有效YOLO结果，切1280×720按其框映射的局部ROI精定位，期间暂停YOLO；不再按三靶角度条件自动进入。结束/取消及原有退出条件后恢复640×360。本轮板卡未联网，用户要求先完成本地修改，未部署、构建或运行板端。此条覆盖下文此前持续720p和0x62完全被动的历史说明。 block/disc/target共用buffer_count=2；此前720p性能表保留为旧版本历史结果。

2026-11-24按FPS稳定与提升优先的要求，cameras.object.buffer_count设为2，保持1280×720/MJPG/30FPS及原像素解码。只改变驱动缓冲数量，不增加采集线程或Python图像队列。旧配置缺省1，QR等角色继续旧默认。

buffer_count只接受1～4整数，bool/float不接受。显式配置在_open_capture设置后回读CAP_PROP_BUFFERSIZE，拒绝驱动静默忽略；失败释放已打开设备并报告CAMERA_BUFFER_COUNT_REJECTED。capture_signature包含缓冲数，发生变化需按既有切换流程重开；默认block/target均2，仍复用同一720p流。状态capture_buffer_count用于核对。

同条件相机＋YOLO短测1/2/3缓冲约14.87/23.04/23.23FPS，3几乎不再提速且排队更长。最终完整应用正常网页800ms轮询＋预览约22FPS，5秒窗口约21.8～22.2FPS；40ms完整状态压力请求约17FPS，解除后恢复22。不能把正常与高频压力工况混为同一FPS。

双缓冲代价：短测驱动时间戳到图像交付年龄均值约52→70ms，P95约85ms；这是交付年龄估计，不是曝光到MCU的延迟。未来较慢的圆盘/精定位模式需单独测新鲜度与FPS，不能把当前YOLO结果推广过去。

保持原OpenCV解码，是因为同JPEG系统TurboJPEG约15.9ms、当前OpenCV约14.5ms，且像素完全一致，替换无速度收益。没有启用快速低质量解码、降低分辨率、改变模型或阈值。

配置继承独立物块/有雷达/无雷达共同生效；测试见tests/test_camera_lifecycle.py，实测、备份和命令见artifacts/capture_opt_20261124/REPORT.md。最终服务保持停止，自启设置保留。
